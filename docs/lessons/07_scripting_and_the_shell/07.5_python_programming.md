## Why operators use Python

Shell is excellent for connecting existing commands. Python is better when the task needs data structures, clearer branching, JSON handling, or tests around non-trivial logic.

Python is a good fit for:

- parsing structured text or JSON
- grouping and counting records
- calling HTTP APIs
- validating input before a change
- writing portable scripts with clearer error handling
- building tools that will grow beyond a one-off command

Python is not automatically better than shell. If the task is "run three existing commands and print their output," shell may be simpler. If the task is "load data, make decisions, and produce a structured result," Python usually wins.

## Find the Python interpreter

Many systems have more than one Python installed. Check what you are using:

```sh
command -v python3
python3 --version
```

Avoid assuming `python` exists or points to Python 3. Use `python3` in Linux operator notes unless the local environment documents another command.

Run a one-line command:

```sh
python3 -c 'print("hello from python")'
```

Run a script:

```sh
python3 script.py
```

## Script structure

A small operational Python script should make its inputs and outputs obvious.

```python
#!/usr/bin/env python3

from pathlib import Path


def main() -> int:
    path = Path("/var/log")
    print(f"target={path}")
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

The `main()` function gives the script a clear entry point. Returning an integer makes success and failure visible to the shell.

## Arguments

Use `argparse` for command-line arguments instead of manually reading `sys.argv`.

```python
#!/usr/bin/env python3

import argparse
from pathlib import Path


def parse_args() -> argparse.Namespace:
    parser = argparse.ArgumentParser(description="Inspect a directory.")
    parser.add_argument("path", nargs="?", default=".", help="directory to inspect")
    return parser.parse_args()


def main() -> int:
    args = parse_args()
    path = Path(args.path)
    print(f"path={path}")
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

Run it:

```sh
python3 inspect.py /tmp
```

Good argument parsing gives the next operator `--help` for free:

```sh
python3 inspect.py --help
```

## Paths and files

Use `pathlib` for path handling:

```python
from pathlib import Path

path = Path("/tmp/example.txt")
print(path.name)
print(path.exists())
```

Read text with an explicit encoding:

```python
from pathlib import Path

text = Path("app.log").read_text(encoding="utf-8")
print(text)
```

For large files, read line by line instead of loading the whole file:

```python
from pathlib import Path

with Path("app.log").open("r", encoding="utf-8") as handle:
    for line in handle:
        if "status=500" in line:
            print(line.rstrip())
```

## Errors and exit codes

Operational scripts should fail loudly and clearly.

```python
from pathlib import Path


def require_file(path: Path) -> None:
    if not path.is_file():
        raise FileNotFoundError(f"not a file: {path}")
```

Catch expected errors near the entry point:

```python
def main() -> int:
    try:
        require_file(Path("app.log"))
    except FileNotFoundError as exc:
        print(f"error: {exc}", file=sys.stderr)
        return 1
    return 0
```

A nonzero exit code lets shell, cron, CI, or another script know the run failed.

## JSON output

Python's standard library handles JSON well:

```python
import json

summary = {"status": "ok", "errors": 0}
print(json.dumps(summary, indent=2, sort_keys=True))
```

JSON output is useful when another tool or agent needs to consume the result. Keep human-readable logs and machine-readable JSON separate when possible. A common pattern is:

- normal status messages to standard error
- JSON payload to standard output

That way, another program can safely read standard output.

## Virtual environments

A virtual environment isolates Python packages for one project.

Create one:

```sh
python3 -m venv .venv
```

Use it without relying on shell activation:

```sh
.venv/bin/python --version
.venv/bin/python -m pip install -r requirements.txt
```

Activation is convenient for interactive work:

```sh
. .venv/bin/activate
python --version
```

For scripts, CI, and runbooks, prefer explicit paths such as `.venv/bin/python` so the interpreter is unambiguous.

## Read-only log summary example

This script reads a log file, counts status codes, and prints JSON. It does not modify files.

```python
#!/usr/bin/env python3

import argparse
import json
import re
import sys
from collections import Counter
from pathlib import Path

STATUS_RE = re.compile(r"status=(\d{3})")


def parse_args() -> argparse.Namespace:
    parser = argparse.ArgumentParser(description="Summarize status codes in a log.")
    parser.add_argument("logfile", help="log file to inspect")
    return parser.parse_args()


def summarize(path: Path) -> dict[str, object]:
    counts: Counter[str] = Counter()
    lines = 0

    with path.open("r", encoding="utf-8") as handle:
        for line in handle:
            lines += 1
            match = STATUS_RE.search(line)
            if match:
                counts[match.group(1)] += 1

    return {"file": str(path), "lines": lines, "status_codes": dict(sorted(counts.items()))}


def main() -> int:
    args = parse_args()
    path = Path(args.logfile)

    if not path.is_file():
        print(f"error: not a file: {path}", file=sys.stderr)
        return 1

    print(json.dumps(summarize(path), indent=2, sort_keys=True))
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

This is the kind of work that becomes awkward in shell but stays readable in Python.

## Hands-on practice

Run these commands on a disposable VM, container, or lab machine.

1. Create a sample log:

    ```sh
    mkdir -p /tmp/python-lab
    cat > /tmp/python-lab/app.log <<'EOF'
    2026-05-10T12:00:01Z path=/api/orders status=200 user=alice
    2026-05-10T12:00:02Z path=/api/orders status=503 user=bob
    2026-05-10T12:00:03Z path=/api/users status=404 user=carol
    2026-05-10T12:00:04Z path=/api/orders status=500 user=dave
    EOF
    ```

2. Save the read-only summary script:

    ```sh
    cat > /tmp/python-lab/summarize_status.py <<'EOF'
    #!/usr/bin/env python3

    import json
    import re
    import sys
    from collections import Counter
    from pathlib import Path

    status_re = re.compile(r"status=(\d{3})")
    path = Path(sys.argv[1]) if len(sys.argv) > 1 else Path("/tmp/python-lab/app.log")

    if not path.is_file():
        print(f"error: not a file: {path}", file=sys.stderr)
        raise SystemExit(1)

    counts = Counter()
    with path.open("r", encoding="utf-8") as handle:
        for line in handle:
            match = status_re.search(line)
            if match:
                counts[match.group(1)] += 1

    print(json.dumps({"file": str(path), "status_codes": dict(sorted(counts.items()))}, indent=2))
    EOF
    ```

3. Run it:

    ```sh
    python3 /tmp/python-lab/summarize_status.py
    ```

4. Verify failure behavior:

    ```sh
    python3 /tmp/python-lab/summarize_status.py /tmp/python-lab/missing.log
    printf 'exit_status=%s\n' "$?"
    ```
