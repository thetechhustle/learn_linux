### Browsing SMB File Shares

Before you mount an SMB share or troubleshoot an access problem, you often need
to answer a simpler question: what does the server expose, and what can this
account actually see?

On Linux, `smbclient` is the standard low-risk tool for that job. It lets you
list shares, connect to one share, inspect directories, and copy test files
without changing the local mount table.

!!! abstract "What you will learn"
    - Use `smbclient` to list SMB shares from Linux.
    - Interpret common share-list output.
    - Browse a share without mounting it.
    - Separate anonymous, guest, local-user, domain-user, and Kerberos tests.
    - Capture useful evidence when browsing fails.

!!! success "Operator principle"
    Browse first, mount later. A read-only SMB client check is usually safer
    than turning an unknown share into a persistent filesystem dependency.

## Install The Client Tools

Most Linux distributions package `smbclient` separately from the Samba server.

```bash
sudo apt install smbclient
```

On RHEL, Fedora, or similar systems:

```bash
sudo dnf install samba-client
```

Verify the tool:

```bash
smbclient --version
```

## List Shares On A Server

The basic share-list command is:

```bash
smbclient -L //fileserver.example.com -U alice
```

If the environment uses a Windows domain or Active Directory domain, include it
explicitly:

```bash
smbclient -L //fileserver.example.com -U EXAMPLE/alice
```

You can also pass the domain separately:

```bash
smbclient -L //fileserver.example.com -U alice -W EXAMPLE
```

Typical output looks like this:

```text
Sharename       Type      Comment
---------       ----      -------
IPC$            IPC       IPC Service
print$          Disk      Printer Drivers
projects        Disk      Project files
homes           Disk      Home directories
```

Read the output carefully:

| Column | Meaning |
| --- | --- |
| `Sharename` | The name used in paths such as `//server/projects`. |
| `Type` | `Disk` for file shares, `Printer` for print shares, `IPC` for control channels. |
| `Comment` | Human-facing server comment, not an access-control guarantee. |

Administrative shares such as `IPC$`, `ADMIN$`, or `C$` may appear on some
servers. Their presence does not mean ordinary users can access them.

## Connect To One Share

After you identify a candidate share, connect to it:

```bash
smbclient //fileserver.example.com/projects -U EXAMPLE/alice
```

Inside the interactive prompt:

```text
smb: \> pwd
smb: \> ls
smb: \> cd reports
smb: \reports\> ls
smb: \reports\> quit
```

You can run a single command non-interactively with `-c`:

```bash
smbclient //fileserver.example.com/projects -U EXAMPLE/alice -c 'ls'
```

That is useful in troubleshooting notes because it produces a compact evidence
trail.

## Test Different Authentication Paths

SMB access depends heavily on identity. A server may show a share list to one
identity and hide it from another.

Anonymous or guest-style test:

```bash
smbclient -L //fileserver.example.com -N
```

Local or workgroup account:

```bash
smbclient -L //fileserver.example.com -U alice
```

Domain account:

```bash
smbclient -L //fileserver.example.com -U EXAMPLE/alice
```

Kerberos ticket, when the client is joined or otherwise configured for the
realm:

```bash
kinit alice@EXAMPLE.COM
smbclient -L //fileserver.example.com -k
```

If these produce different results, record that difference. It usually points
to an authentication, domain, group-membership, or share-visibility issue
rather than a generic network failure.

## Browse Without Leaking Passwords

Avoid placing passwords directly on the command line. They can end up in shell
history, audit logs, or process listings.

Prefer prompting:

```bash
smbclient //fileserver.example.com/projects -U EXAMPLE/alice
```

For scripted diagnostics, use a root-owned credentials file:

```bash
sudo install -m 0600 -o root -g root /dev/null /etc/samba/creds-projects
sudoedit /etc/samba/creds-projects
```

Example file:

```ini
username=alice
password=replace-with-real-secret
domain=EXAMPLE
```

Then:

```bash
smbclient //fileserver.example.com/projects --authentication-file=/etc/samba/creds-projects -c 'ls'
```

## Useful `smbclient` Commands

Inside an `smbclient` session:

| Command | Purpose |
| --- | --- |
| `ls` | List files in the current remote directory. |
| `cd dirname` | Change remote directory. |
| `pwd` | Show current remote directory. |
| `get file` | Download one file to the local directory. |
| `put file` | Upload one local file to the remote share. |
| `mkdir name` | Create a remote directory if permissions allow it. |
| `del file` | Delete a remote file if permissions allow it. |
| `help` | Show available commands. |
| `quit` | Exit the session. |

Treat write commands such as `put`, `mkdir`, and `del` as changes to a remote
system. In production, confirm you are in the expected directory and use a
clearly named test file.

## Check Protocol And Name Resolution

Sometimes browsing fails before authentication. Confirm the server name,
address, and SMB port first:

```bash
getent hosts fileserver.example.com
nc -vz fileserver.example.com 445
```

If the server requires a specific SMB dialect, test it explicitly:

```bash
smbclient -L //fileserver.example.com -U EXAMPLE/alice -m SMB3
```

Older servers may need `-m SMB2`. Avoid SMB1 unless you are isolating a legacy
exception and understand the security risk.

## Troubleshooting Browsing Failures

Use the error message to choose the next layer.

| Symptom | Likely cause | First check |
| --- | --- | --- |
| `NT_STATUS_LOGON_FAILURE` | Bad password, wrong domain, disabled account | Retry with explicit `DOMAIN/user`; check account status. |
| `NT_STATUS_ACCESS_DENIED` | Account is valid but lacks share/list permission | Test another allowed account; inspect server share ACLs. |
| `NT_STATUS_BAD_NETWORK_NAME` | Share does not exist or is hidden from that account | Re-run `smbclient -L`; confirm exact share name. |
| `Connection to ... failed` | Network, firewall, DNS, or server outage | `getent hosts`, `nc -vz server 445`, server status. |
| Empty share list | Server hides unreadable shares or guest listing is disabled | Authenticate with a known allowed account. |

For more detail, raise the debug level:

```bash
smbclient -L //fileserver.example.com -U EXAMPLE/alice -d 3
```

Do not paste high-debug output into public tickets without reviewing it. Debug
logs can include usernames, domains, paths, and server details.

## Hands-On Practice

Use a lab Samba server or a known disposable share.

1. Install `smbclient`.
2. Run `smbclient -L //server -N` and record whether anonymous listing works.
3. Run `smbclient -L //server -U user` and compare the result.
4. Connect to one `Disk` share and run `pwd` and `ls`.
5. Run the same `ls` with `-c` from a non-interactive command.
6. Intentionally use a wrong share name and record the error.
7. Intentionally use a wrong password and record the different error.
8. Write a short note explaining which failure came from naming, which came
   from authentication, and which came from authorization.
