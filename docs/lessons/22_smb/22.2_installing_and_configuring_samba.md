### Installing and Configuring Samba

Samba turns a Unix-like system into an SMB file server. The risky part is not the package install; it is publishing the right directory to the right users without accidentally creating a guest-writable file drop.

!!! abstract "What you will learn"
    - Install the Samba server packages on common Linux distributions.
    - Identify the important Samba services and configuration files.
    - Create a small authenticated share with conservative defaults.
    - Validate the configuration before restarting services.
    - Troubleshoot the first layer of package, service, firewall, and account problems.

!!! example "Field story"
    A project team needs a small file share that Windows, macOS, and Linux clients can all reach. You need to stand it up quickly, but you also need a clear evidence trail: which package was installed, which service is listening, which local users can authenticate, what path is shared, and how you tested the configuration before users depend on it.

!!! success "Operator principle"
    Start with an authenticated, least-privilege share. Add guest access, write access, or broad network exposure only when the requirement is explicit and documented.

## Install the packages

Package names vary by distribution, but the server package is usually named `samba`.

=== "Debian / Ubuntu"

    ```bash
    sudo apt update
    sudo apt install samba
    ```

=== "Fedora / RHEL / Rocky / AlmaLinux"

    ```bash
    sudo dnf install samba samba-client
    ```

=== "Arch Linux"

    ```bash
    sudo pacman -S samba
    ```

After installation, confirm that the expected tools are available:

```bash
smbd --version
testparm --version
```

On systemd-based distributions, the main file-serving daemon is usually `smbd`. NetBIOS browsing and older name-service behavior may use `nmbd`; Active Directory domain controller deployments use additional Samba services. For a basic file server, focus on `smbd` first.

```bash
systemctl status smbd --no-pager
```

Some distributions call the unit `smb.service` instead of `smbd.service`:

```bash
systemctl list-unit-files 'smb*' 'nmb*'
```

## Know the configuration files

The main configuration file is:

```text
/etc/samba/smb.conf
```

Before editing it, make a timestamped backup:

```bash
sudo cp /etc/samba/smb.conf /etc/samba/smb.conf.$(date +%Y%m%d%H%M).bak
```

Use `testparm` to see Samba's parsed view of the configuration. This catches syntax errors and also reveals defaults that are not written explicitly in the file.

```bash
testparm -s
```

## Create a conservative share

Create a directory owned by a dedicated Unix group. This keeps the share's filesystem permissions separate from one user's home directory.

```bash
sudo groupadd smb-projects
sudo mkdir -p /srv/samba/projects
sudo chgrp smb-projects /srv/samba/projects
sudo chmod 2770 /srv/samba/projects
```

The leading `2` in `2770` sets the setgid bit on the directory. New files created inside inherit the directory's group, which helps shared-team permissions stay predictable.

Add the Unix users who should access the share:

```bash
sudo usermod -aG smb-projects alice
```

Samba has its own password database. A Unix account must exist first, then you enable that account for SMB authentication:

```bash
sudo smbpasswd -a alice
sudo smbpasswd -e alice
```

Now add a share definition to `/etc/samba/smb.conf`:

```ini
[projects]
    path = /srv/samba/projects
    browseable = yes
    read only = no
    guest ok = no
    valid users = @smb-projects
    force group = smb-projects
    create mask = 0660
    directory mask = 2770
```

Important options in this example:

- `path` is the local directory exported through SMB.
- `guest ok = no` requires authentication.
- `valid users = @smb-projects` limits access to members of the Unix group.
- `force group` keeps files group-owned by the shared project group.
- `create mask` and `directory mask` prevent world-readable files inside the share.

Avoid examples that combine `public = yes`, `guest ok = yes`, and `writable = yes` unless you truly intend to build an unauthenticated writeable share. That pattern is useful in a throwaway lab, but dangerous on a real network.

## Validate before restarting

Run the parser after every edit:

```bash
testparm
```

If `testparm` reports errors, fix them before touching the running service. When the configuration parses cleanly, restart or reload Samba:

```bash
sudo systemctl restart smbd
```

Confirm that the service is running:

```bash
systemctl status smbd --no-pager
```

Confirm that the server is listening for SMB traffic:

```bash
ss -ltnp | grep -E ':(139|445)\b'
```

Port `445/tcp` is the normal direct SMB port. Port `139/tcp` is older NetBIOS session service support.

## Check the firewall

If clients cannot connect from another machine, verify the local firewall before changing Samba again.

On firewalld systems:

```bash
sudo firewall-cmd --add-service=samba --permanent
sudo firewall-cmd --reload
sudo firewall-cmd --list-services
```

On UFW systems:

```bash
sudo ufw allow Samba
sudo ufw status
```

Only open SMB ports on networks where the server is meant to provide file sharing. Do not expose SMB directly to the public internet.

## Test from the server

List the configured shares through Samba's own client tool:

```bash
smbclient -L localhost -U alice
```

Connect to the share and run a small read/write test:

```bash
smbclient //localhost/projects -U alice
smb: \> mkdir test-from-smb
smb: \> rmdir test-from-smb
smb: \> quit
```

If this local test fails, fix the server before debugging remote clients.

## Common failure patterns

- **`tree connect failed: NT_STATUS_ACCESS_DENIED`**: The SMB user exists, but `valid users`, group membership, or filesystem permissions do not permit access.
- **`session setup failed: NT_STATUS_LOGON_FAILURE`**: The Samba password database does not have the account, the account is disabled, or the password is wrong.
- **Clients time out**: `smbd` is not running, the firewall blocks port 445, or the client is reaching the wrong host.
- **Files are created with surprising permissions**: Check `create mask`, `directory mask`, `force group`, and the parent directory mode.
- **Configuration looks right but behavior did not change**: Re-run `testparm -s`, then restart `smbd` and confirm the correct unit name for the distribution.

## Hands-on practice

Use a disposable VM or lab host.

1. Install Samba and record the package version.
2. Create `/srv/samba/projects` with a dedicated group.
3. Add one local user to the group and enable that user with `smbpasswd`.
4. Add the `[projects]` share to `smb.conf`.
5. Run `testparm`, restart `smbd`, and confirm port 445 is listening.
6. Use `smbclient` from the server to create and remove a test directory.
7. Write a short rollback note that includes the backup `smb.conf` path and the commands needed to disable the share.
