### 20.4 Attachment and Low-Level Management of Drives

Low-level drive management is the work you do before a filesystem or
volume manager becomes useful. It includes detecting a disk, confirming
what it is, reading or creating partition tables, rescanning devices, and
checking kernel messages for errors.

This work is powerful because it operates close to the data. The same
tools that prepare a new disk can erase the wrong one. Slow down, collect
evidence, and keep a written note of the device you intend to touch.

!!! abstract "What you will learn"
    - Detect, rescan, and read existing signatures on attached drives before making any change.
    - Create partition tables and remove drives safely while respecting LVM, RAID, swap, and mounts.
    - Recognize destructive commands (`mkfs`, `wipefs`, `dd`, `parted mklabel`, `pvcreate`, `mdadm --create`) and safer read-only habits.

## The Operator Mindset

Before making a low-level storage change, answer these questions:

- Which exact device am I changing?
- What evidence proves that device is the intended target?
- Does the device already contain signatures, partitions, or data?
- Is there a backup or recovery path if the operation is wrong?
- Which services or users depend on this storage?
- What command will prove the change worked?

If you cannot answer those questions, stay in read-only inspection mode.

## Detect Attached Drives

Start with kernel and block-device views:

```bash
lsblk -o NAME,MODEL,SERIAL,SIZE,TYPE,ROTA,TRAN,FSTYPE,MOUNTPOINTS
sudo blkid
sudo dmesg | tail -50
sudo journalctl -k --since "10 minutes ago"
```

`lsblk` gives the current block-device tree. `blkid` reports known
filesystem and partition signatures. Kernel logs often reveal attachment,
reset, timeout, or media errors that the simple device list does not show.

For hardware detail:

```bash
sudo lshw -class disk -class storage
udevadm info --query=property --name=/dev/sda
```

Replace `/dev/sda` with the device you are inspecting.

## Rescan After Attachment

Many disks appear automatically. If a newly attached disk does not show
up, first verify the platform, hypervisor, cable, controller, or cloud
volume attachment. Then rescan the relevant bus.

For SCSI-style hosts:

```bash
for host in /sys/class/scsi_host/host*; do
  echo "- - -" | sudo tee "$host/scan"
done
```

For a resized block device, you may need to reread the partition table:

```bash
sudo partprobe /dev/sdb
sudo udevadm settle
lsblk /dev/sdb
```

Do not use rescans as a substitute for confirming that the platform really
attached or resized the volume.

## Read Existing Signatures

Before creating or changing partitions, check for existing metadata:

```bash
sudo wipefs -n /dev/sdb
sudo file -s /dev/sdb
sudo file -s /dev/sdb1
```

The `-n` flag tells `wipefs` to print signatures without erasing them. If
you see an existing filesystem, RAID member, LVM physical volume, swap
signature, or partition table, stop and identify the owner.

Useful LVM and RAID checks:

```bash
sudo pvs
sudo vgs
sudo lvs
cat /proc/mdstat
sudo mdadm --detail --scan
```

Low-level storage work should never surprise LVM, RAID, or the application
owner.

## Partition Tables

A partition table records how a disk is divided. Modern Linux systems
usually use GPT. Older systems may still use MBR.

Inspect a disk:

```bash
sudo parted /dev/sdb print
sudo fdisk -l /dev/sdb
```

Create a simple GPT layout:

```bash
sudo parted /dev/sdb --script mklabel gpt
sudo parted /dev/sdb --script mkpart primary 1MiB 100%
sudo partprobe /dev/sdb
lsblk /dev/sdb
```

These commands are destructive to existing partition metadata. Use them
only on a confirmed target disk.

## Device Names and Persistent Paths

Device names such as `/dev/sdb` are assigned by discovery order and can
change. Persistent paths are better for documentation and automation.

Inspect persistent links:

```bash
ls -l /dev/disk/by-id/
ls -l /dev/disk/by-uuid/
ls -l /dev/disk/by-path/
```

Common rules:

- Use filesystem UUIDs in `/etc/fstab`.
- Use `/dev/disk/by-id/` when a script must target a specific physical or
  virtual disk.
- Use multipath devices for SAN-backed storage.
- Record cloud volume IDs beside Linux device names in runbooks.

The goal is to make it possible for another operator to map the Linux
device back to the real storage asset.

## Safely Removing a Drive

Before removing a drive, identify what is mounted or using it:

```bash
findmnt
lsblk -f
sudo lsof +f -- /mount/point
```

Stop dependent services, unmount filesystems, deactivate volume groups if
needed, and flush pending writes:

```bash
sudo systemctl stop example.service
sudo umount /mount/point
sync
```

For a SCSI-style disk, you can ask the kernel to delete the device after
it is no longer in use:

```bash
echo 1 | sudo tee /sys/block/sdb/device/delete
```

Use this only after confirming the device is no longer mounted or used by
LVM, RAID, swap, or an application.

## Low-Level Health Checks

Drive health depends on the transport and controller, but these commands
are a good starting point:

```bash
lsblk -o NAME,MODEL,SERIAL,SIZE,ROTA,TRAN
sudo smartctl -a /dev/sda
sudo nvme smart-log /dev/nvme0
sudo journalctl -k --since "1 hour ago"
```

Watch for:

- I/O errors.
- Link resets.
- Media errors.
- Reallocated or pending sectors.
- NVMe temperature and media-warning fields.
- Sudden disconnects.

SMART and NVMe data are signals, not guarantees. A disk can fail without a
perfectly clear warning, and virtual disks may not expose physical health.

## Dangerous Commands

These commands can be legitimate, but they deserve extra care:

| Command | Risk | Safer habit |
| --- | --- | --- |
| `mkfs` | Erases filesystem structures | Confirm target with `lsblk` and `wipefs -n` |
| `wipefs` | Removes signatures | Use `wipefs -n` first |
| `dd` | Copies or overwrites raw blocks | Avoid unless a runbook requires it |
| `parted mklabel` | Replaces partition table | Confirm backups and target disk |
| `pvcreate` | Initializes LVM metadata | Check for existing signatures first |
| `mdadm --create` | Creates RAID metadata | Confirm member devices and order |

If a command writes to a raw block device, pause before pressing Enter.

## Hands-on Practice

Use a loopback disk for safe practice:

```bash
truncate -s 512M /tmp/drive-lab.img
sudo losetup --find --show /tmp/drive-lab.img
```

The command prints a loop device such as `/dev/loop0`. Inspect it:

```bash
lsblk /dev/loop0
sudo wipefs -n /dev/loop0
sudo parted /dev/loop0 --script mklabel gpt
sudo parted /dev/loop0 --script mkpart primary 1MiB 100%
sudo partprobe /dev/loop0
lsblk /dev/loop0
```

Clean up:

```bash
sudo losetup -d /dev/loop0
rm /tmp/drive-lab.img
```

Replace `/dev/loop0` with the loop device your system printed.
