### 03.3 Extensions to the Standard Access Control Model

!!! abstract "What you will learn"
    - Explain when standard owner/group/mode permissions are not enough.
    - Inspect and use POSIX ACLs without changing file ownership.
    - Recognize the risks and operational uses of setuid, setgid, and sticky bits.

!!! example "Field story"
    A shared project directory belongs to one team, but a contractor needs read-only access to a specific subdirectory for one week. Changing the directory's owner or broadening the group would affect too many people. An ACL can express the exception, but only if you inspect it, document it, and remove it later.

!!! success "Operator principle"
    Use extended access controls to express exceptions, not to hide unclear ownership.

## Hands-on practice

Run these on a disposable VM, container, or lab machine. ACL and special-bit commands can affect real access decisions.

1. Create a lab directory:

    ```sh
    mkdir -p /tmp/acl-lab/project
    touch /tmp/acl-lab/project/report.txt
    ls -ld /tmp/acl-lab/project
    ls -l /tmp/acl-lab/project/report.txt
    ```

2. Inspect ACL support:

    ```sh
    getfacl /tmp/acl-lab/project
    getfacl /tmp/acl-lab/project/report.txt
    ```

3. Add a read-only ACL entry for your current user on the file:

    ```sh
    setfacl -m "u:$(id -un):r--" /tmp/acl-lab/project/report.txt
    getfacl /tmp/acl-lab/project/report.txt
    ls -l /tmp/acl-lab/project/report.txt
    ```

    Notice the `+` in `ls -l` output. It indicates extended ACL metadata is present.

4. Remove the ACL entry:

    ```sh
    setfacl -x "u:$(id -un)" /tmp/acl-lab/project/report.txt
    getfacl /tmp/acl-lab/project/report.txt
    ```

5. Practice setgid on a lab directory:

    ```sh
    chmod g+s /tmp/acl-lab/project
    ls -ld /tmp/acl-lab/project
    ```

    On directories, setgid helps new files inherit the directory's group. This is useful for shared team folders.

6. Observe the sticky bit on `/tmp`:

    ```sh
    ls -ld /tmp
    ```

    The `t` near the end of the mode string shows the sticky bit. In shared writable directories, it prevents users from deleting files they do not own.

7. Clean up:

    ```sh
    rm -rf /tmp/acl-lab
    ```

## POSIX ACLs

The standard permission model gives one owner, one group, and one "other" class. ACLs add named users and groups without changing the file's primary owner or group.

Use ACLs when:

- one extra user needs access to a file or directory;
- a service account needs read-only access to a specific path;
- changing the owning group would affect too many users;
- you need a temporary exception that can be reviewed and removed.

Avoid ACLs when:

- nobody understands the current owner/group model;
- the exception should really be a group membership change;
- the filesystem or backup tooling does not preserve ACLs;
- the access rule will become permanent policy without documentation.

Key commands:

```sh
getfacl path
setfacl -m u:alice:rx path
setfacl -m g:auditors:r-- path
setfacl -x u:alice path
setfacl -b path
```

`setfacl -b` removes all extended ACL entries from a path. Use it carefully.

## Default ACLs on directories

Default ACLs apply to new files and directories created inside a directory:

```sh
setfacl -m d:g:auditors:rx /tmp/acl-lab/project
getfacl /tmp/acl-lab/project
```

Default ACLs do not rewrite every existing file. They shape future creation. During an incident, check both the directory default ACL and the file's actual ACL before assuming access should work.

## Special permission bits

Linux also extends the standard model with special mode bits:

- setuid on an executable: run the program with the file owner's effective user ID.
- setgid on an executable: run the program with the file group's effective group ID.
- setgid on a directory: make new entries inherit the directory's group.
- sticky bit on a directory: only the file owner, directory owner, or root can remove entries.

Inspect them with:

```sh
find /usr/bin -perm -4000 -type f -maxdepth 1 2>/dev/null
find /usr/bin -perm -2000 -type f -maxdepth 1 2>/dev/null
ls -ld /tmp
```

Setuid and setgid executables are sensitive because they intentionally cross privilege boundaries. Do not add these bits to scripts or custom binaries unless you understand the security consequences and have a reviewed operational reason.

## Safe handoff checklist

For any ACL or special-bit change, write down:

```text
Path:
Current owner/group/mode:
Existing ACL:
Requested access:
Command used:
Verification command:
Rollback command:
Expiration or review date:
```

This prevents hidden access exceptions from becoming permanent mystery state.
