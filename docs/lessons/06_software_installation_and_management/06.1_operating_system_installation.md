## 06.1 Operating System Installation

!!! abstract "What you will learn"
    - Choose an installation target that matches the machine's workload and support model.
    - Verify installation media before it touches a disk.
    - Plan partitioning, boot mode, network, users, and recovery access before starting the installer.
    - Prove after first boot that the system is patched, reachable, and ready for package management.

!!! example "Field story"
    A small team is replacing an aging internal build server. The work is not "click through the installer." The real job is to preserve the old server's role, install the new system without wiping the wrong disk, prove that the new host boots in the expected mode, and leave a recovery path if the handoff fails.

!!! success "Operator principle"
    Treat an OS install as a change window: collect facts first, make the smallest irreversible choices possible, and verify the result before handing the system to users.

Operating system installation is the foundation for every later software-management task. Package managers, service managers, security updates, logging, and recovery all depend on choices made here: distribution, release track, disk layout, boot mode, network setup, user accounts, and update policy.

Do this work on a disposable VM, spare machine, or cloud test instance while learning. A real installer can erase disks, change boot entries, overwrite encryption headers, and make a machine unreachable.

## Choose the distribution and release

Start with support requirements, not preference. A laptop, web server, container host, firewall, and classroom VM can all be "Linux" but need different tradeoffs.

- Use a long-term support release when stability and predictable security updates matter.
- Use a faster-moving release when hardware support or newer developer tooling matters more than long maintenance windows.
- Prefer the distribution your team already documents, monitors, and patches.
- Confirm whether the target system needs vendor support, FIPS mode, SELinux/AppArmor defaults, cloud images, or specific package versions.

Record the decision in a short install note:

```text
Host: build-02
Purpose: internal CI worker
Distro/release: Ubuntu Server 24.04 LTS
Reason: team standard, long support window, existing Ansible role coverage
Rollback: keep build-01 online until build jobs pass on build-02
```

## Verify the installer image

Download installation media only from the distribution's official site or mirror list. Then verify the checksum before writing it to USB or attaching it to a VM.

```bash
sha256sum distro-installer.iso
cat SHA256SUMS
```

For a stronger check, verify the signed checksum file when the distribution provides one:

```bash
gpg --verify SHA256SUMS.gpg SHA256SUMS
```

Do not skip this step for production installs. A bad image can waste a maintenance window; an untrusted image can compromise the system before it ever joins the network.

## Plan the irreversible choices

Before launching the installer, collect enough evidence to avoid choosing the wrong disk, boot mode, or network identity.

```bash
lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS,MODEL,SERIAL
ip link
ip route
```

Plan these items explicitly:

- **Target disk:** identify it by size, model, serial number, and current use.
- **Boot mode:** use UEFI unless the hardware or workload requires legacy BIOS.
- **Partitioning:** decide whether the host needs separate `/`, `/home`, `/var`, `/boot`, swap, LVM, RAID, or encryption.
- **Network:** choose DHCP, static addressing, hostname, DNS, and remote-access policy.
- **Accounts:** create named admin users; avoid shared root access as the default operating model.
- **Update source:** confirm mirrors, proxies, and whether the first boot should install security updates immediately.
- **Recovery path:** know how to boot rescue media, revert a VM snapshot, or return traffic to the old host.

!!! warning "Disk safety"
    Installer disk screens are the dangerous part of this lesson. If a disk contains data you care about, stop and back it up before continuing. In a lab, use a new VM disk or a spare disposable drive so a mistake is recoverable.

## Install with a validation checklist

Most Linux installers ask the same operational questions even when the interface differs:

- language, keyboard, and time zone
- disk target and partitioning
- boot loader location
- network settings
- package selection or installation profile
- initial user account and authentication method
- update and telemetry preferences

Pause on any screen that changes disks, boot entries, or remote access. Compare it to your install note before accepting it.

## Prove first boot

After the first reboot, capture evidence before handing the system off.

```bash
cat /etc/os-release
uname -a
timedatectl
lsblk -f
findmnt
ip addr
ip route
systemctl --failed
```

Then apply the distribution's supported update workflow and reboot if the kernel, boot loader, libc, or core security packages changed.

```bash
# Debian/Ubuntu
sudo apt update
sudo apt upgrade

# Fedora/RHEL family
sudo dnf upgrade
```

Finish with a short install record:

```text
Installed release: Ubuntu 24.04.2 LTS
Kernel after update: 6.8.0-xx-generic
Boot mode: UEFI
Disk layout: LVM on /dev/nvme0n1, separate /boot
Network: static 10.0.12.42/24, DNS 10.0.12.10
Failed units: none
Rollback window: old host remains online until Friday 17:00
```

## Troubleshooting first-boot problems

- If the system does not boot, return to firmware setup and confirm UEFI versus legacy boot mode and boot order.
- If the boot loader appears but Linux does not start, use the installer rescue mode to inspect `/boot`, `/etc/fstab`, and the root filesystem UUIDs.
- If the system boots but has no network, compare `ip link`, `ip addr`, `ip route`, DNS settings, switch port state, and cloud security groups.
- If login fails, use console access or rescue mode; do not keep retrying remote password guesses.
- If package updates fail, confirm time sync, DNS, proxy settings, repository configuration, and certificate trust.

## Hands-on practice

Run this lab on a disposable VM.

1. Download a current Linux server ISO and verify its SHA256 checksum.
2. Create a VM with one blank disk and a network adapter.
3. Write a five-line install note covering distro choice, disk plan, network plan, account plan, and rollback.
4. Install the OS using the note.
5. After first boot, collect the evidence commands from this lesson.
6. Apply updates, reboot if needed, and run `systemctl --failed`.
7. Summarize what changed between installer boot, first boot, and post-update boot.
