## 13.4 IP Addresses: The Gory Details

IP addresses are not just labels. They determine whether Linux treats a
destination as local, which source address it chooses, which gateway it uses,
and whether a reply can make it back. When a host has the wrong address or
prefix, higher-level services fail in confusing ways.

This lesson focuses on the details administrators actually use during
operations.

!!! abstract "What you will learn"
    - Interpret IPv4 and IPv6 addresses, prefix lengths, and the network, host, and broadcast roles of an address.
    - Recognize private, loopback, link-local, and documentation ranges, and what a `169.254.x.x` or `fe80::` address implies.
    - Use `ip route get`, `ip neigh`, and `arping` to check source-address selection and detect duplicate addresses.

## Address, Prefix, and Interface

Linux assigns IP addresses to interfaces. The address identifies the host on a
network. The prefix length tells Linux which part of the address describes the
local network.

Check current addresses with:

```bash
ip -brief addr
ip addr show
```

Example IPv4 address:

```text
192.168.8.42/24
```

The `/24` means the first 24 bits identify the network. In normal dotted decimal
terms, that is the `192.168.8.0` network. Addresses from `192.168.8.1` through
`192.168.8.254` are usually usable host addresses on that subnet, depending on
local policy.

Example IPv6 address:

```text
2001:db8:1234:10::42/64
```

In many IPv6 LANs, `/64` is the standard host subnet size. Do not assume IPv6 is
just "longer IPv4"; neighbor discovery, router advertisements, and address
autoconfiguration change the operational details.

## Network, Host, and Broadcast

For many IPv4 subnets, three address roles matter:

- network address: identifies the subnet itself
- host address: assigned to an interface
- broadcast address: reaches all hosts on the subnet

For `192.168.8.42/24`:

| Role | Address |
| --- | --- |
| Network | `192.168.8.0` |
| Host example | `192.168.8.42` |
| Broadcast | `192.168.8.255` |

Do not assign the network or broadcast address to a normal host. If you see one
configured accidentally, expect odd connectivity failures.

IPv6 does not use broadcast the same way. It uses multicast and neighbor
discovery instead.

## Private, Public, and Link-Local Addresses

Address ranges carry operational meaning.

Common private IPv4 ranges:

| Range | Typical use |
| --- | --- |
| `10.0.0.0/8` | large private networks, cloud VPCs, labs |
| `172.16.0.0/12` | private networks, containers, enterprise LANs |
| `192.168.0.0/16` | home and small-office LANs |

Other useful ranges:

| Range | Meaning |
| --- | --- |
| `127.0.0.0/8` | IPv4 loopback |
| `169.254.0.0/16` | IPv4 link-local fallback |
| `::1/128` | IPv6 loopback |
| `fe80::/10` | IPv6 link-local |
| `2001:db8::/32` | documentation examples only |

If a host has a `169.254.x.x` IPv4 address, DHCP probably failed. If an IPv6
address starts with `fe80::`, it is link-local and normally needs an interface
scope to be useful.

Example:

```bash
ping -6 fe80::1%eth0
```

The `%eth0` tells Linux which link-local network to use.

## CIDR and Prefix Lengths

CIDR notation writes the prefix length after a slash. You will see it in Linux
commands, cloud consoles, firewall rules, VPN routes, and container networks.

Common IPv4 prefixes:

| Prefix | Approximate host capacity | Common use |
| --- | ---: | --- |
| `/32` | one host | exact host route |
| `/30` | two usable hosts | point-to-point links |
| `/24` | 254 usable hosts | small LAN |
| `/16` | 65,534 usable hosts | large private segment |
| `/8` | millions | broad private or legacy ranges |

The smaller the prefix number, the larger the network. `10.0.0.0/8` is much
larger than `10.0.1.0/24`.

Ask the kernel what a prefix means by checking the resulting route:

```bash
ip route
ip route get 10.0.1.25
```

## Source Address Selection

Hosts often have more than one address:

- Ethernet plus Wi-Fi
- VPN plus local LAN
- IPv4 plus IPv6
- public plus private cloud interfaces
- container bridge plus host interface

Linux must choose a source address for outgoing traffic. The route decision is
the quickest way to see what it will choose:

```bash
ip route get 8.8.8.8
ip route get 192.168.8.1
```

If the selected source address is wrong, replies may return to the wrong place
or be dropped by policy. This is common with VPNs, containers, multiple default
routes, and cloud hosts with several interfaces.

## Static, Dynamic, and Reserved Addresses

An address can be configured manually, assigned by DHCP, generated through IPv6
autoconfiguration, or reserved in an external system.

Static addresses are useful for infrastructure:

- routers
- DNS servers
- monitoring endpoints
- storage appliances
- hypervisors
- lab nodes that need predictable access

Dynamic addresses are easier for clients:

- laptops
- phones
- temporary VMs
- most containers
- short-lived test hosts

For important hosts, prefer reservation at the authoritative source of truth:
DHCP reservation, cloud private IP assignment, infrastructure-as-code, or a
documented network inventory. Manually editing a host without updating the
source of truth creates future conflicts.

## Duplicate Addresses

Two systems using the same IP address can cause intermittent and misleading
failures. Symptoms include:

- connections sometimes reach the wrong machine
- SSH host-key warnings
- ARP or neighbor table entries changing unexpectedly
- services appearing and disappearing
- one host working only while another is offline

Useful checks:

```bash
ip neigh
arping -D -I <interface> <ipv4-address>
```

`arping -D` performs duplicate-address detection for IPv4. Use it carefully and
only on the relevant interface.

## Address Evidence During Incidents

When documenting an address-related issue, collect:

```bash
ip -brief addr
ip route
ip route get <destination>
ip neigh
resolvectl status
```

For cloud or container systems, also record the platform's view:

- cloud instance private/public addresses
- security group or firewall attachment
- container network and published ports
- VPN address and advertised routes
- load balancer target address

The goal is to compare what Linux believes with what the network control plane
believes.

## Safe Change Pattern

Address changes can cut off remote access. Before making one:

1. Confirm you have console or out-of-band access.
2. Save the current state:

   ```bash
   ip -brief addr
   ip route
   ```

3. Make the smallest reversible change.
4. Test from the host and from another host.
5. Keep the old session open until the new path is proven.
6. Update DHCP, DNS, inventory, and runbooks if the change is permanent.

Avoid changing a remote host's only reachable address over the same SSH session
unless you have a rollback path.

## Hands-on Practice

Use a lab VM, disposable cloud instance, or container host.

1. Record all interface addresses:

   ```bash
   ip -brief addr
   ```

2. Identify the prefix for the primary interface and write the local subnet in
   plain language.

3. Ask Linux which source address it would use for two destinations:

   ```bash
   ip route get 1.1.1.1
   ip route get <your-default-gateway>
   ```

4. Inspect neighbor information:

   ```bash
   ip neigh
   ```

5. Write a short note that answers:

   - which address is local to the host
   - which prefix defines the local subnet
   - which source address Linux uses for Internet-bound traffic
   - whether any address looks link-local, temporary, or unexpected
