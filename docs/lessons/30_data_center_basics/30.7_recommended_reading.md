# 30.7 Recommended Reading

!!! abstract "What you will learn"
    - Build a practical reading path for data center fundamentals.
    - Separate facility concepts from Linux operator responsibilities.
    - Choose references that help during real incidents and planning work.

Data center basics are easier to learn when you connect the physical world to operating-system evidence. Racks, power, cooling, reliability, security, and tools all matter because Linux hosts run inside those constraints.

This reading path focuses on practical operator judgment. The goal is not to become a facilities engineer overnight. The goal is to understand enough to ask better questions, document the right facts, and avoid treating physical-infrastructure problems like ordinary software bugs.

## Start With Operator Context

Before diving into specialized references, review your own environment:

- Where are your important Linux hosts?
- Which are physical, virtual, or cloud-hosted?
- Who controls the rack, power, cooling, and physical access?
- What evidence can you collect without entering the room?
- Who handles remote-hands requests?
- What is the escalation path after hours?

This local context makes every reading source more useful.

## Core Reading Lanes

Use these lanes in order.

### 1. Facility Basics

Focus on:

- Rack units and rack layout.
- Power distribution.
- Cooling and airflow.
- Cable management.
- Fire detection and suppression.
- Remote-hands procedures.

Useful search terms:

```text
data center rack units front to back airflow
hot aisle cold aisle basics
rack PDU A feed B feed redundant power
data center remote hands request best practices
```

### 2. Reliability and Maintenance

Focus on:

- Redundant components.
- Independent distribution paths.
- Concurrent maintainability.
- Fault tolerance.
- Maintenance windows.
- Failure domains.

Useful search terms:

```text
data center concurrent maintainability
data center fault tolerance failure domain
planned maintenance data center power path
```

### 3. Physical and Management-Plane Security

Focus on:

- Badge and visitor controls.
- Rack and cage access.
- Asset tracking.
- Drive handling.
- Out-of-band management security.
- Audit log correlation.

Useful search terms:

```text
out of band management security idrac ilo ipmi
data center physical security access logs
secure drive disposal chain of custody
```

### 4. Linux Evidence

Focus on:

- Reboot history.
- Kernel logs.
- Hardware sensors.
- Network interfaces.
- Authentication logs.
- Service state before and after maintenance.

Useful commands to revisit:

```bash
uptime
last -x | head
journalctl -b -1 -p warning..alert --no-pager
journalctl -k --no-pager | grep -Ei 'thermal|power|fan|throttle|critical'
ss -tulpen
ip addr show
```

## Books and Long-Form References

Good long-form references include:

- **Unix and Linux System Administration Handbook** for operator mindset, troubleshooting discipline, and production administration habits.
- **Site Reliability Engineering** from Google for reliability thinking, service objectives, toil, and incident response.
- **The Practice of System and Network Administration** for operational process, documentation, and service ownership.
- Vendor data center design guides for concrete language around power, cooling, rack layout, and facilities operations.

Use books for mental models. Use vendor and facility documentation for the exact rules in your environment.

## Vendor Documentation

When you manage real hardware, prefer primary documentation:

- Dell iDRAC documentation.
- HPE iLO documentation.
- Lenovo XClarity documentation.
- Supermicro IPMI/BMC documentation.
- Ubiquiti, Cisco, Juniper, Arista, or other network-device docs for switch and management-network behavior.
- UPS and PDU vendor documentation.

Primary docs matter because management interfaces, firmware, sensors, and event logs vary by platform.

## Standards and Frameworks

Useful standards and framework areas:

- Uptime Institute tier concepts for facility redundancy language.
- TIA data center cabling and infrastructure concepts.
- ISO/IEC 27001 for information security management context.
- NIST cybersecurity guidance for access control, audit, and incident response concepts.

Do not memorize standards numbers first. Learn what operational question each standard helps answer.

## What to Read During an Incident

During an active incident, avoid broad reading. Look for exact evidence:

- Host event logs.
- BMC/iDRAC/iLO/IPMI event logs.
- Provider status pages.
- Facility maintenance notices.
- Remote-hands ticket history.
- Network change records.
- Monitoring timelines.
- Recent deployment or configuration changes.

The best incident reading is usually local and specific.

## Evaluate Sources Carefully

Be careful with:

- Vendor marketing pages that overstate reliability.
- Blog posts that do not distinguish facility reliability from application availability.
- Old hardware guides for modern servers.
- Forum advice that assumes physical access you do not have.
- Security advice that encourages shortcuts around badge, identity, or change controls.

Prefer sources that explain constraints, failure modes, and verification steps.

## Practice Plan

For the next week, do one small exercise per day:

1. Map one host to its physical or provider location.
2. Record how that host receives power.
3. Record how you would check thermal or hardware events.
4. Identify the management interface and who can access it.
5. Write a remote-hands inspection request.
6. Identify the host's largest failure domain.
7. Update your local notebook with what you learned.
