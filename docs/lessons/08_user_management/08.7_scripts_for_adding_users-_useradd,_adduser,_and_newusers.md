### 08.7 Tools for Adding Users: useradd, adduser, and newusers

!!! abstract "What you will learn"
    - Choose between `useradd`, `adduser`, and `newusers` for different account-creation jobs.
    - Inspect account defaults before creating users.
    - Create a user with a home directory, shell, comment, and group membership.
    - Verify the account after creation instead of assuming the command did what you expected.
    - Handle batch account files carefully because they can contain passwords.

!!! example "Field story"
    A new support contractor starts tomorrow. They need an account on one Linux jump host, access to the `support` group, and a normal home directory. Later in the week, ten lab students need short-lived accounts for a workshop. Both jobs create users, but they should not use the same workflow.

!!! success "Operator principle"
    Account creation is not finished when the command exits. It is finished when you can prove the username, UID, groups, home directory, shell, and password state match the request.

Linux gives you several tools for creating accounts. They all touch the same account databases, but they are built for different operating styles:

- `useradd` is a low-level, script-friendly account creation command.
- `adduser` is a higher-level helper, commonly interactive on Debian and Ubuntu systems.
- `newusers` is a batch provisioning command that reads account definitions from a file.

Do not edit `/etc/passwd`, `/etc/shadow`, or `/etc/group` by hand for normal account creation. Use the account tools so locks, defaults, home-directory setup, and supporting files are handled consistently.

## Preflight checks

Before you create an account, collect the facts that make the change predictable.

Check whether the user already exists:

```bash
getent passwd andrea
```

Check whether the target group exists:

```bash
getent group support
```

Check valid login shells:

```bash
cat /etc/shells
```

Inspect the current `useradd` defaults:

```bash
useradd -D
```

The defaults may include the base home directory, default shell, account expiration policy, mail spool behavior, and skeleton directory. Do not assume every distribution uses the same defaults.

## Creating one account with useradd

`useradd` is useful when you want a clear, repeatable command. It is common in scripts, build procedures, and administrator runbooks.

A bare `useradd` command may create only the account database entries. Depending on local defaults, it may not create a home directory, choose the shell you expect, or set a password.

Use explicit options when the result matters:

```bash
sudo useradd -m -s /bin/bash -c "Andrea Ramos, support contractor" -G support andrea
```

The options mean:

- `-m` creates the home directory if it does not already exist.
- `-s /bin/bash` sets the login shell.
- `-c "..."` stores a human-readable comment in the GECOS field.
- `-G support` adds the user to the supplementary `support` group.

Set the initial password separately:

```bash
sudo passwd andrea
```

If this is a service account, do not give it a normal interactive password. Service accounts usually need a locked password and a restricted shell unless the application has a documented reason to log in interactively:

```bash
sudo useradd -r -s /usr/sbin/nologin -c "Backup service account" backupsvc
sudo passwd -l backupsvc
```

On some systems, `nologin` may live at `/sbin/nologin`. Check `/etc/shells` and local policy before choosing the shell.

## Creating one account with adduser

`adduser` is easier for one-off human accounts on distributions where it is available. On Debian and Ubuntu, it is usually an interactive helper around lower-level account tools. It prompts for a password and user details, and it normally creates a home directory.

```bash
sudo adduser andrea
```

Use `adduser` when you are working directly at the terminal and want prompts. Use `useradd` when you need exact options in a documented command or script.

Be careful when moving between distributions. On some systems, `adduser` may be missing, may be a symlink to `useradd`, or may behave differently from the Debian-style helper. Confirm behavior with the local manual page:

```bash
man adduser
```

## Batch creation with newusers

`newusers` creates or updates multiple users from a colon-separated file. It is useful for lab environments, classroom systems, and approved bulk provisioning jobs.

The input format resembles passwd-style fields:

```text
username:password:uid:gid:comment:home_directory:shell
```

Example file:

```text
lab01:ChangeMe-OnlyInLab::1001:Lab User 01:/home/lab01:/bin/bash
lab02:ChangeMe-OnlyInLab::1001:Lab User 02:/home/lab02:/bin/bash
```

The file is sensitive because it can contain initial passwords. Protect it before use:

```bash
chmod 600 new_users.txt
```

Then run:

```bash
sudo newusers new_users.txt
```

After provisioning, verify the accounts and remove the sensitive input file according to your site's retention policy. Do not leave password-bearing files in shell history, shared folders, tickets, chat logs, or source control.

## Verification

Verify the result after any account creation workflow.

Check the passwd database:

```bash
getent passwd andrea
```

Check UID, primary group, and supplementary groups:

```bash
id andrea
```

Check the home directory:

```bash
ls -ld /home/andrea
```

Check password status:

```bash
sudo passwd -S andrea
```

Check the shell:

```bash
getent passwd andrea | cut -d: -f7
```

If the user needs group access added after creation, use `usermod -aG` so existing supplementary groups are preserved:

```bash
sudo usermod -aG support andrea
```

The `-a` matters. Without it, `usermod -G` replaces the user's supplementary group list.

## Handoff notes

For a real account request, record:

- Who requested the account.
- The username created.
- Whether it is a human or service account.
- The groups assigned.
- The shell and home directory.
- The verification commands you ran.
- Any expiration or offboarding date.

This gives the next administrator enough context to audit, disable, or remove the account later.

## Hands-on practice

Run these commands only on a disposable VM, container, or lab machine.

1. Inspect current defaults:

    ```bash
    useradd -D
    ```

2. Create a disposable lab user:

    ```bash
    sudo useradd -m -s /bin/bash -c "Disposable lab user" lab-andrea
    ```

3. Set a temporary password:

    ```bash
    sudo passwd lab-andrea
    ```

4. Verify the account:

    ```bash
    getent passwd lab-andrea
    id lab-andrea
    ls -ld /home/lab-andrea
    sudo passwd -S lab-andrea
    ```

5. Write a short lab note explaining which files or databases changed and which command proved each change.
