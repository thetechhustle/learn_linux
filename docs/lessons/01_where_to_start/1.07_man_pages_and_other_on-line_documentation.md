## 1.07 Man Pages and Other On-line Documentation

Linux work depends on documentation. The best operators do not memorize every
option; they know where the trustworthy reference is, how to read it quickly,
and how to prove that a command applies to the system in front of them.

This lesson introduces the documentation sources you will use most often:
local manual pages, command help, packaged documentation, distribution docs,
vendor docs, and community posts.

!!! abstract "What you will learn"
    - Use `man`, `--help`, `apropos`, and package docs to answer command questions.
    - Distinguish local system documentation from generic online advice.
    - Read manual-page syntax without guessing.
    - Capture documentation references in troubleshooting notes.

!!! success "Operator principle"
    Prefer documentation that matches the system you are changing: same command,
    same distribution family, same major version, and same package source.

## Start with local documentation

Manual pages are installed on the system and usually match the versions of the
commands available there.

```bash
man ls
```

Manual pages are commonly divided into numbered sections. The most common
sections are:

| Section | Topic |
| --- | --- |
| `1` | User commands |
| `2` | System calls |
| `3` | Library calls |
| `4` | Devices and special files |
| `5` | File formats and configuration files |
| `8` | System administration commands |

Some names exist in more than one section. For example, `passwd` can refer to
the user command or the password file format:

```bash
man 1 passwd
man 5 passwd
```

When a page has multiple sections, include the section in your notes:

```text
Reference checked: passwd(5), shadow(5), usermod(8)
```

## Search for the right page

Use `apropos` or `man -k` when you know the topic but not the command name:

```bash
apropos password
man -k filesystem
```

Use `whatis` when you want a one-line summary:

```bash
whatis sshd
whatis fstab
```

If the manual database is stale on a lab system, your distribution may provide
`mandb` to rebuild it. Do not run broad maintenance commands on production just
to search documentation unless you understand the impact.

## Read a man page efficiently

Inside most man-page viewers:

- Press `/` and type a word to search.
- Press `n` for the next match.
- Press `N` for the previous match.
- Press `q` to quit.

Useful sections to scan first:

- `NAME`: one-line purpose.
- `SYNOPSIS`: command syntax.
- `DESCRIPTION`: behavior and important defaults.
- `OPTIONS`: flags and arguments.
- `FILES`: related configuration files.
- `EXAMPLES`: usage examples, when present.
- `SEE ALSO`: related commands and file formats.

Do not skip `FILES` and `SEE ALSO`. They often point to the config file or
companion command that actually answers the operational question.

## Understand syntax markers

Manual pages use compact notation:

```text
command [OPTION]... FILE...
```

Read it as:

- `command`: literal command name.
- `[OPTION]`: optional argument.
- `...`: may repeat.
- `FILE`: placeholder; replace it with a real file path.

Do not type brackets or ellipses unless the documentation explicitly says they
are literal characters.

For example, this syntax:

```text
cp [OPTION]... SOURCE DEST
```

becomes a real command like:

```bash
cp -a /etc/ssh/sshd_config /tmp/sshd_config.backup
```

## Use command help for quick checks

Many commands expose short help:

```bash
ls --help
ssh -h
systemctl --help
```

Help output is faster than a full manual page, but it may be incomplete. Use it
for quick option checks, then use the manual page or distribution documentation
when behavior matters.

## Look for package documentation

Some packages install extra documentation under `/usr/share/doc`.

```bash
ls /usr/share/doc
ls /usr/share/doc/openssh-client
```

Common useful files include:

- `README`
- `NEWS`
- `CHANGELOG`
- `examples/`
- sample configuration files

These files can contain distribution-specific notes that are not obvious in the
upstream manual page.

## Match online documentation to your system

Online documentation is useful, but source quality matters.

Prefer:

- Official distribution documentation for your distro and release.
- Upstream project documentation for the exact software you are running.
- Cloud-provider documentation for provider-specific behavior.
- Vendor release notes and migration guides.

Be cautious with:

- Old blog posts.
- Forum answers that do not mention versions.
- Commands copied without explanation.
- Guides for a different distribution family.
- AI-generated answers with no verifiable source.

Before using online guidance, capture system identity:

```bash
cat /etc/os-release
uname -r
command --version
```

Then compare that evidence with the documentation's target platform.

## Good documentation notes

A useful troubleshooting note includes:

```text
System: Ubuntu 24.04 LTS
Command/package: openssh-server 1:9.6p1-3ubuntu13
Question: Which file controls sshd password authentication?
References checked: sshd_config(5), sshd(8), Ubuntu server docs
Conclusion: PasswordAuthentication is configured in /etc/ssh/sshd_config or included files.
Next action: inspect effective sshd config before changing anything.
```

This is better than:

```text
Found answer online.
```

## Lab: answer from local docs first

On a lab Linux system, answer these without using a web search first:

1. Which manual section documents `/etc/fstab`?
2. Which option makes `du` show human-readable sizes?
3. Which files does `sshd_config(5)` mention?
4. Which related pages does `man systemctl` list under `SEE ALSO`?

Commands to try:

```bash
man fstab
man du
man sshd_config
man systemctl
apropos filesystem
whatis crontab
```

Write a short note with the command you used, the reference page, and the answer.
