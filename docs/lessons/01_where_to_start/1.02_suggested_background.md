# 1.02 Suggested Background

You do not need to be a programmer, network engineer, or career system
administrator before learning Linux. You do need enough context to ask useful
questions, avoid reckless changes, and build confidence from evidence instead
of guesswork.

This course assumes curiosity, patience, and regular hands-on practice. The
background below is helpful because it gives each new Linux concept somewhere
to land.

!!! abstract "What you will learn"
    - Identify the computer, command-line, networking, and troubleshooting skills
      that make Linux easier to learn.
    - Separate useful prerequisites from topics you can safely learn as you go.
    - Prepare a simple lab environment where mistakes are recoverable.
    - Build the habit of recording commands, observations, and results.

!!! success "Operator principle"
    You do not need to know everything before touching Linux, but you should know
    whether you are practicing in a safe lab or changing a real system.

## Computer Fundamentals

Linux exposes the operating system more directly than many desktop environments.
It helps to understand a few basic ideas before you go deep:

- A process is a running program.
- Memory is temporary workspace used by running programs.
- Filesystems organize data into directories and files.
- Storage devices hold data after the machine powers off.
- Users and groups control who can read, write, and execute resources.
- The kernel coordinates hardware, processes, memory, filesystems, and network
  access.

You do not need a formal operating systems class. You should be comfortable
asking, "Which resource is this command inspecting or changing?"

## Command-Line Comfort

Most serious Linux administration happens at a shell prompt. You should expect
to spend time typing commands, reading output, and editing plain-text files.

Useful starting skills include:

- moving through directories with `pwd`, `ls`, and `cd`
- reading files with `cat`, `less`, `head`, and `tail`
- searching text with `grep` or `rg`
- understanding absolute paths such as `/var/log/syslog`
- understanding relative paths such as `../notes.txt`
- using command history to repeat or adjust earlier commands
- copying command output into a lab note

Speed is not the goal at first. Accuracy is. Type slowly, read the command
before pressing Enter, and learn what each flag changes.

## Text Editing

Linux systems are configured largely through text files. You should be able to
open a file, make a small change, save it, and exit the editor.

Pick one terminal editor early:

- `nano` is friendly for beginners.
- `vim` is common on servers and worth learning over time.

Before editing important files, make a backup or use a lab machine. A useful
habit is:

```bash
cp /path/to/file /path/to/file.bak
```

Then edit the original, test the result, and keep the backup until the change is
proven safe.

## Networking Basics

Linux is widely used for servers, cloud systems, routers, containers, and
automation. Basic networking vocabulary will make later chapters easier.

You should recognize these ideas:

- an IP address identifies a host on a network
- a subnet groups addresses that can usually reach each other directly
- a gateway sends traffic toward other networks
- DNS turns names into IP addresses
- a port identifies a service on a host
- TCP is connection-oriented; UDP is message-oriented
- firewalls allow or block traffic based on rules

You will learn Linux-specific tools later, but the basic mental model matters:
when a service is unreachable, you investigate name resolution, routing,
listening ports, firewall rules, and application health separately.

## Programming And Scripting

Programming experience helps, but it is not required. The most useful skill for
Linux operations is understanding automation in small pieces.

Helpful background includes:

- reading a simple shell script
- recognizing variables and conditionals
- understanding exit codes
- using loops carefully
- knowing when a script changes files, users, packages, or services

Shell scripting will appear throughout Linux work because it turns repeated
manual steps into repeatable procedures. Learn it gradually. Avoid running
scripts from the internet until you have read them and understand their impact.

## Version Control

Git is not a Linux prerequisite, but it is a powerful safety habit for scripts,
configuration, notes, and documentation.

At minimum, it helps to understand:

- a repository stores tracked history
- a commit records a specific change
- a branch isolates work
- a diff shows what changed
- a remote shares changes with others

Even if you are not writing software, version control gives you a way to answer
"what changed?" after a system starts behaving differently.

## Build A Safe Lab

The best background is a place to practice without fear. Use one of these:

- a local virtual machine
- a disposable cloud instance
- a spare laptop or small server
- a container for command-line practice
- a Linux subsystem or shell environment on your workstation

Do not learn risky administrative commands on production systems. Treat commands
that affect disks, users, packages, firewall rules, boot configuration, or
services as real changes.

Before a lab session, write down:

- what machine you are using
- what operating system and version it runs
- what you plan to test
- how you will undo or discard the change

## Hands-On Practice

Use a disposable Linux system.

1. Identify the distribution and version:

   ```bash
   cat /etc/os-release
   ```

2. Record the kernel version:

   ```bash
   uname -a
   ```

3. Identify your current user and groups:

   ```bash
   id
   ```

4. List the current directory and save the output in a note:

   ```bash
   pwd
   ls -la
   ```

5. Write a short paragraph answering:

   - What system am I practicing on?
   - Is this safe to break?
   - What did I learn from the commands?
