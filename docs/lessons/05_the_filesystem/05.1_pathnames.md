### 05.1 Pathnames: Locate Files Without Guessing

A pathname is the text address of a file or directory. Operators use pathnames
constantly: reading logs, editing configuration, checking mounts, copying
artifacts, rotating backups, and repairing deployments. A wrong path can make a
correct command dangerous, so path handling is an operational skill, not just a
navigation trick.

!!! abstract "What you will learn"
    - Distinguish absolute, relative, canonical, and symbolic-link paths.
    - Use read-only commands to prove where a path points.
    - Recognize common pathname hazards in scripts and incident response.
    - Build safer command habits before changing files.

!!! success "Operator principle"
    Prove the path before you modify the target. `pwd`, `ls -ld`, `readlink`,
    `realpath`, `stat`, and mount checks are cheap compared with repairing a
    change made in the wrong directory.

## Absolute and Relative Paths

An absolute path starts at the root directory `/`:

```bash
/etc/ssh/sshd_config
/var/log
/home/alex/report.txt
```

A relative path starts from the current working directory:

```bash
docs/lessons
../archive
./deploy.sh
```

Before using a relative path in a command, confirm where you are:

```bash
pwd
ls -la
```

Use absolute paths in runbooks, cron jobs, systemd units, and automation unless
there is a clear reason not to. Humans can recover from a surprising working
directory. Scripts usually cannot.

## Special Path Components

These components appear often:

- `/`: filesystem root.
- `.`: current directory.
- `..`: parent directory.
- `~`: current user's home directory, expanded by the shell.
- `-`: previous directory for commands such as `cd -`.

Examples:

```bash
cd /var/log
pwd
ls .
ls ..
cd -
```

Be careful with `..` in cleanup commands. This is harmless:

```bash
ls ../archive
```

This deserves extra verification before running:

```bash
rm -r ../archive
```

## Canonical Paths and Symlinks

A pathname can point through one or more symbolic links. The text you type may
not be the final location the kernel uses.

Inspect paths without changing them:

```bash
ls -ld /bin /usr/bin
readlink /bin 2>/dev/null || true
realpath /bin 2>/dev/null || true
stat /bin
```

Useful distinctions:

- `ls -l path`: shows whether `path` is a symlink.
- `readlink path`: shows the symlink target if `path` is a symlink.
- `realpath path`: resolves the final canonical path.
- `stat path`: shows file type, ownership, mode, timestamps, and inode metadata.

When editing service configuration, write down the path you edited and the
canonical path if symlinks are involved. That prevents "I edited the wrong copy"
incidents.

## Paths, Mounts, and Filesystems

Two paths that look nearby may live on different filesystems. That matters for
capacity, permissions, performance, backups, and failure modes.

Check the filesystem behind a path:

```bash
df -h /var/log
df -ih /var/log
findmnt /var/log
stat -f /var/log
```

What each command tells you:

- `df -h`: block capacity for the filesystem containing the path.
- `df -ih`: inode capacity for the filesystem containing the path.
- `findmnt`: mount source, target, and options.
- `stat -f`: filesystem type and summary metadata.

When a deployment says "No space left on device," do not only inspect the path in
the error message. Also inspect the filesystem and inode counts for that path.

## Quoting and Unsafe Names

Pathnames can contain spaces, tabs, newlines, leading dashes, and shell glob
characters. Good scripts assume hostile pathnames.

Prefer quoting variables:

```bash
path="/srv/app/current release"
ls -ld "$path"
```

Use `--` before path arguments that could begin with `-`:

```bash
rm -- "$path"
```

Use `find -print0` with tools that support null-delimited input:

```bash
find /srv/app/logs -type f -name '*.log' -print0 | xargs -0 ls -lh
```

Avoid parsing `ls` output in scripts. Use `find`, `stat`, shell globs with care,
or a language with filesystem APIs.

## Read-Only Investigation Pattern

When a path-related incident arrives:

1. Capture the exact path from the error.
2. Confirm the current working directory if relative paths are involved:

    ```bash
    pwd
    ```

3. Inspect the target and parent directory:

    ```bash
    ls -ld "$path" "$(dirname "$path")"
    stat "$path" 2>/dev/null || true
    ```

4. Resolve symlinks:

    ```bash
    realpath "$path" 2>/dev/null || true
    ```

5. Check filesystem capacity and mount details:

    ```bash
    df -h "$path" 2>/dev/null || df -h "$(dirname "$path")"
    df -ih "$path" 2>/dev/null || df -ih "$(dirname "$path")"
    findmnt -T "$path" 2>/dev/null || true
    ```

6. Only then choose a fix: create a missing directory, correct ownership,
   update configuration, free space, or change the command path.

## Hands-On Practice

Run this in a disposable lab directory:

```bash
tmpdir=$(mktemp -d)
mkdir -p "$tmpdir/releases/v1" "$tmpdir/current"
touch "$tmpdir/releases/v1/app.conf"
ln -s "$tmpdir/releases/v1/app.conf" "$tmpdir/current/app.conf"

ls -ld "$tmpdir/current/app.conf"
readlink "$tmpdir/current/app.conf"
realpath "$tmpdir/current/app.conf"
stat "$tmpdir/current/app.conf"
df -h "$tmpdir/current/app.conf"

rm -rf "$tmpdir"
```

Write down:

- The path you typed.
- The symlink target.
- The canonical path.
- The filesystem that contained the file.
