### 05.4 File Types

!!! abstract "What you will learn"
    - Identify Linux file types from `ls -l`, `stat`, `file`, and `find`.
    - Explain why regular files, directories, links, devices, FIFOs, and sockets behave differently.
    - Choose safer commands before deleting, copying, archiving, or troubleshooting unfamiliar paths.
    - Build a short evidence trail for "this path is not what it looks like" incidents.

!!! example "Field story"
    A deployment cleanup removes what looks like an ordinary stale file under `/tmp`, but it is actually a Unix socket used by a running service. The service stops accepting local requests until it is restarted. Before changing unfamiliar paths, prove the file type and the process or subsystem that owns it.

!!! success "Operator principle"
    Treat the first character in `ls -l` as a safety signal, not decoration.

Linux exposes many system objects as files. The pathname tells you where an object lives, but the file type tells you how the kernel handles reads, writes, metadata, and process interaction.

## Read the type evidence

Start with commands that do not modify anything:

```bash
ls -ld /etc/passwd /etc /dev/null /tmp
stat --format '%F %n' /etc/passwd /etc /dev/null /tmp
file /etc/passwd /bin/sh
```

In long `ls` output, the first character is the file type:

```text
-rw-r--r-- 1 root root  1268 Apr 20 12:00 /etc/passwd
drwxr-xr-x 1 root root  4096 Apr 20 12:00 /etc
lrwxrwxrwx 1 root root     7 Apr 20 12:00 /bin/sh -> dash
crw-rw-rw- 1 root root 1, 3 Apr 20 12:00 /dev/null
```

The remaining permission bits still matter, but the leading type character changes what those bits mean.

| Type | `ls -l` marker | What it represents | Common evidence command |
| --- | --- | --- | --- |
| Regular file | `-` | Text, binary data, scripts, images, logs, archives | `file PATH` |
| Directory | `d` | A mapping from names to inodes | `ls -ld PATH` |
| Symbolic link | `l` | A path that points to another path | `readlink PATH` |
| Character device | `c` | Byte-stream device interface | `ls -l /dev/null` |
| Block device | `b` | Storage device interface | `lsblk` |
| FIFO / named pipe | `p` | One-way process communication endpoint | `stat PATH` |
| Unix socket | `s` | Local process communication endpoint | `ss -xl` |

## Regular files

Regular files hold data. They can be empty, plain text, executable programs, compressed archives, images, database files, or anything else an application writes.

Use `file` when the extension is missing or misleading:

```bash
file ./backup ./script ./download
```

Do not assume that `*.log`, `*.sh`, or `*.tar.gz` is truthful. Names are conventions; file content and metadata are evidence.

## Directories

Directories contain names that point to other filesystem objects. Directory permissions control listing, creating, deleting, and traversing names inside the directory.

Check the directory itself with `-d`; otherwise `ls` shows the directory contents:

```bash
ls -ld /var/log
stat --format '%F %A %U:%G %n' /var/log
```

Before removing a directory tree, prove the target is the intended path:

```bash
pwd
realpath ./candidate-directory
find ./candidate-directory -maxdepth 2 -type d -print
```

## Symbolic links

A symbolic link stores a pathname to another location. The target can be valid, missing, relative, absolute, or replaced after you inspect it.

```bash
ls -l /bin/sh
readlink /bin/sh
readlink -f /bin/sh
```

Be careful with recursive copy, ownership, and deletion commands around links. Decide whether the operation should affect the link itself or the target it references.

## Device files

Device files under `/dev` are interfaces to kernel device drivers. Character devices transfer streams of bytes. Block devices represent storage that can contain partitions, filesystems, or raw data.

Read-only inspection is usually safe:

```bash
ls -l /dev/null /dev/zero
lsblk -o NAME,TYPE,SIZE,FSTYPE,MOUNTPOINTS
findmnt
```

Do not run write commands such as `dd`, `mkfs`, or `wipefs` against a device unless you have identified the exact device, captured the current mount state, and have explicit approval for destructive storage work.

## FIFOs and sockets

FIFOs and Unix sockets are communication endpoints. They often appear in runtime directories such as `/run`, `/var/run`, or application-specific temporary directories.

```bash
find /run -maxdepth 2 -type s -print 2>/dev/null | head
find /run -maxdepth 2 -type p -print 2>/dev/null | head
ss -xl
```

Removing a socket or FIFO can interrupt a running service even when no disk data is lost. If one appears stale, first identify the owning service or process:

```bash
sudo lsof PATH
systemctl status SERVICE
```

## Find by type

`find` can target objects by type. This is useful for audits and cleanup plans.

```bash
find /tmp -maxdepth 1 -type f -print
find /tmp -maxdepth 1 -type d -print
find /tmp -maxdepth 1 -type l -print
find /run -maxdepth 2 -type s -print 2>/dev/null
```

Use `-print` first. Add actions such as `-delete`, `-exec rm`, or `-exec chmod` only after reviewing the exact candidate list.

## Disposable lab

Run this in a temporary directory on a lab machine:

1. Create examples:

    ```bash
    tmpdir="$(mktemp -d)"
    cd "$tmpdir"
    touch regular.txt
    mkdir directory
    ln -s regular.txt symlink-to-regular
    mkfifo named-pipe
    ```

2. Inspect the types:

    ```bash
    ls -l
    stat --format '%F %n' regular.txt directory symlink-to-regular named-pipe
    find . -maxdepth 1 -printf '%y %p\n' | sort
    ```

3. Compare link behavior:

    ```bash
    readlink symlink-to-regular
    cat symlink-to-regular
    rm regular.txt
    ls -l symlink-to-regular
    readlink -f symlink-to-regular || true
    ```

4. Clean up:

    ```bash
    cd /
    rm -rf "$tmpdir"
    ```
